Leadly.ai — Outreach Engine & RBAC Validation

01

Project Overview

Leadly.ai is an enterprise sales engagement and automated outreach SaaS platform. Sales teams use it to import large prospect lists, enrich company data, configure multi-channel outreach sequences (email, scheduled voice calls, LinkedIn tasks), and track deal conversions.

As Associate SQA Engineer, I owned test design and execution across campaign builders, bulk CSV ingestion routines, webhook event deliverability, and strict workspace permission isolation (Admin vs. SDR vs. Read-Only).

02

The Challenge

High-volume asynchronous workers present subtle failure modes. During peak email outreach execution, contact lists often include international character sets, accents, and punctuation (e.g., apostrophes in names such as O'Connor).

Additionally, non-admin SDR users could occasionally trigger bulk actions due to missing API authorization checks on the backend endpoint, even though the frontend button was hidden.

03

Test Strategy & Plan

My strategy prioritized end-to-end data integrity and negative security testing:

  • Data Ingestion Edge Cases: Generated test CSV datasets containing 500+ international names, emojis, malformed email addresses, and SQL injection probes.
  • Negative RBAC API Testing: Authored Postman test suites sending authenticated requests with SDR tokens against restricted Admin endpoints (e.g., POST /api/v1/billing, DELETE /api/v1/leads/bulk).
  • Worker Queue Stress: Monitored BullMQ job execution logs under mock concurrency to assert zero dropped outreach messages.
04

Execution & Artifacts

Authored 115+ test cases in Jira and conducted detailed backend audits.

BUG-LDL-209

Email queue worker crashed on CSV leads containing unescaped apostrophes

Severity: Critical Priority: P1 Status: Verified & Closed
Steps to Reproduce
  1. Upload CSV with names like "Patrick O'Connor" via Campaign Import.
  2. Assign variables {{first_name}} and {{last_name}} in outreach template.
  3. Activate outreach campaign and monitor background queue worker.
Expected Result

Apostrophe escaped cleanly; email dispatches with "Dear Patrick O'Connor".

Actual Result

Unescaped quote broke SQL query interpolation, crashing worker process and dropping 142 leads.

Business Impact: Severe campaign stall and prospect loss. Detected during staging regression before customer data was impacted.
05

Automation & Playwright Suite

Engineered automated RBAC boundary checks ensuring lower-tier roles cannot bypass permissions:

tests/e2e/leadly-rbac.spec.js 
const { test, expect } = require('@playwright/test');

test.describe('Leadly.ai — RBAC Permission Boundaries', () => {
  test('SDR role cannot access admin billing or trigger bulk lead export', async ({ page, request }) => {
    // 1. Authenticate as SDR user
    await page.goto('/login');
    await page.getByLabel('Email').fill('sdr-tester@leadly.internal');
    await page.getByLabel('Password').fill('SecureTestPass123!');
    await page.getByRole('button', { name: /sign in/i }).click();

    // 2. Direct navigation attempt to Admin route
    await page.goto('/settings/billing');
    await expect(page).toHaveURL(/\/dashboard/);
    await expect(page.getByText('Access Restricted')).toBeVisible();

    // 3. Negative API contract assertion
    const response = await request.post('/api/v1/leads/export-bulk', {
      headers: { 'Authorization': 'Bearer SDR_SESSION_TOKEN' }
    });
    expect(response.status()).toBe(403);
    const body = await response.json();
    expect(body.error).toBe('INSUFFICIENT_PERMISSIONS');
  });
});

07

Key Learnings & Reflections

Security testing cannot rely on client-side UI visibility alone. Even if a button is absent from the DOM, backend endpoints must always be tested with unauthorized tokens to prevent privilege escalation.

Furthermore, automated sanitization tests on user-supplied strings are critical to ensuring background job queues remain resilient in production.

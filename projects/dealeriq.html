DealerIQ AI — Automotive Dealership CRM

How rigorous regression testing, API contract validation, and Playwright automation uncovered 7 critical defects before a high-stakes dealership demonstration.

Role Associate SQA Engineer

01

Project Overview

DealerIQ AI is a production enterprise CRM platform tailored specifically for automotive dealerships. The application orchestrates high-concurrency workflows including automated inbound and outbound AI voice agents, conversational prospect chatbots, inventory appraisals, sales negotiation pipelines, contract paperwork fee generation, and carrier logistics shipment dispatch.

As the Associate SQA Engineer at Hatzs Dimensions, my mandate was to lead regression cycles, perform systematic API testing via Postman, audit database records via SQL queries, and author maintainable Playwright end-to-end regression suites to protect release stability.

02

The Challenge

Automotive dealerships operate on razor-thin timelines with complex financial calculations. Testing DealerIQ AI presented several unique architectural challenges:

  • High-Frequency Telephony Webhooks: Telephony providers dispatch asynchronous webhook retries within milliseconds. Duplicate call dispositions frequently caused ghost follow-up SMS triggers or race conditions.
  • State Desynchronization in Complex Forms: The Deal paperwork calculator handles dynamic line items (dealer add-ons, documentation fees, trade-in valuations, sales tax). Navigating to other tabs caused React state unmounting and fee drops.
  • Active Filter Memory Loss: Dealership BDC managers rely on compound filters (e.g., "Unread AI Follow-Up" + "High Intent"). Re-sorting table columns wiped active URL query parameters.
03

04

Execution & Artifacts

Authored and executed 140+ test cases in Jira and ClickUp. During the pre-release sprint, I identified 7 critical defects that were logged with exhaustive reproduction steps:

BUG-DIQ-418

Deal paperwork fees table reset upon navigating to Carrier Shipment tab

Severity: High Priority: P1 Status: Verified & Closed
Steps to Reproduce
  1. Open Deal #9482 with active paperwork and custom $850 ceramic coating fee.
  2. Verify calculated contract subtotal displays $42,850.00.
  3. Click "Carrier Shipment" tab to inspect dispatch details.
  4. Click back to "Paperwork & Fees" tab.
Expected Result

State preserved: line items intact and total remains $42,850.00.

Actual Result

Component unmounted; draft accessories dropped; total reset to base MSRP ($42,000.00).

Business Impact: Dealership sales managers would have delivered underquoted paperwork during live customer negotiations. Caught and fixed prior to production rollout.
05

Automation & Playwright Suite

To prevent these regressions from ever recurring, I engineered an automated regression suite using Playwright (JavaScript) following the Page Object Model (POM):

tests/e2e/dealeriq-deals.spec.js 
const { test, expect } = require('@playwright/test');

test.describe('DealerIQ AI — Deals & Paperwork Integrity', () => {
  test('should persist dealer add-ons across tab switches without calculation loss', async ({ page }) => {
    // 1. Navigate to Active Pipeline
    await page.goto('/deals/pipeline');
    await page.getByRole('row', { name: /#9482/i }).click();

    // 2. Add custom accessory line-item
    await page.getByRole('tab', { name: /paperwork/i }).click();
    await page.getByRole('button', { name: /add accessory/i }).click();
    await page.getByLabel('Item Name').fill('Ceramic Coating Protection');
    await page.getByLabel('Price ($)').fill('850.00');
    await page.getByRole('button', { name: /apply/i }).click();

    // Assert calculated total
    await expect(page.locator('#deal-total-display')).toHaveText('$42,850.00');

    // 3. Switch tabs to Carrier Shipment & return
    await page.getByRole('tab', { name: /carrier shipment/i }).click();
    await expect(page.getByText('Carrier Dispatch Parameters')).toBeVisible();

    await page.getByRole('tab', { name: /paperwork/i }).click();

    // Assert state retention
    await expect(page.getByText('Ceramic Coating Protection')).toBeVisible();
    await expect(page.locator('#deal-total-display')).toHaveText('$42,850.00');
  });
});

07

Key Learnings & Reflections

This project underscored that modern single-page applications with complex tab routing cannot rely on naive in-memory state. Implementing automated test assertions that deliberately switch views, sort columns, and simulate network hiccups is essential to discovering desynchronization bugs before customers encounter them.

Furthermore, working hand-in-hand with frontend and backend developers by providing curl reproduction commands and DevTools traces established high engineering trust and accelerated bug fix verification.

BUG-DIQ-418 (1 of 7 in Regression Cycle) Severity: High Priority: P1 Status: Verified Fixed
Env: Staging • Chrome DevTools / macOS

[Dealership CRM Regression] Shipment navigation & paperwork total mismatch when applying active chat filter on qualified deal records

Preconditions

  • Dealership user is authenticated with Sales_Manager role permissions.
  • Lead record has generated paperwork and an active shipment tracking state.

Steps to Reproduce

  1. Navigate to Deals → Paperwork & Shipment and apply the Chat Filter (`Unread AI Follow-up`).
  2. Click on the Shipment Navigation tab to transition from Paperwork Preview to Carrier Dispatch.
  3. Inspect the paperwork fee calculation and network response in Chrome DevTools (`GET /api/v1/deals/paperwork`).
EXPECTED RESULT

Shipment navigation opens the selected deal’s dispatch view while preserving the exact paperwork line-item totals and active chat filter state.

ACTUAL RESULT

Stale state parameter resets the deal context during navigation, causing paperwork data inaccuracy and clearing the active chat filter selection.

BUSINESS IMPACT

Blocks dealership staff from verifying paperwork accuracy during live client demonstrations and causes shipment navigation errors. (Caught & resolved prior to release).

  pm.expect(res.success).to.be.true;

  );
  pm.expect(res.data.ai_call_status).to.eql("SCHEDULED");
});
